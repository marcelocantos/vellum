## Added

- Markdown converts to a PowerPoint deck. A `.pptx` output path, `--to-format pptx`, or MCP `to.format: pptx` writes the deck through pandoc's pptx writer, so the slide carving follows pandoc's rules: a YAML title block becomes the title slide, headings above the slide level become section slides, headings at the slide level one slide each, and `---` starts a new slide. Lists, tables, images, code, inline and display math (as native Office math), footnotes, links, `::: notes` speaker notes, `::: incremental` and `::: columns` all carry through.
- pandoc, not a hand-rolled OOXML writer. pandoc is already a runtime dependency for rich-text import and the clipboard RTF fallback, and its writer already does the layout selection, text-run styling, tables, math and notes that a direct OOXML path would have to re-implement for no fidelity gain. The reader is `gfm+fenced_divs+definition_lists`, which matches vellum's goldmark dialect.
- Three ways in: the bare sugar `vellum deck.md -o deck.pptx`, `vellum convert --from file --to file deck.md --to-format pptx`, and the MCP `convert` tool with a `to.path` ending `.pptx` (or `to.format: pptx`), which reports `to_format: pptx`. `powerpoint` is accepted as a format alias.
- A built-in reference deck ships in the binary: a pinned copy of pandoc's default template (pandoc 3.11, 16:9), always passed as `--reference-doc`, so output does not drift with the installed pandoc. Pick another with `--template <t>` (CLI), `"template": "<t>"` (MCP), or `template:` in `config.yaml`: a `.pptx`/`.potx` path, a bare name resolved under `~/.config/vellum/templates/<name>.pptx` (`$XDG_CONFIG_HOME` honoured), or `default` for the built-in deck. A missing template is a hard error naming the path looked for. Any deck saved from PowerPoint with pandoc's layout names intact works.
- Mermaid blocks land on slides as PNG pictures. The sink renders them through the same concurrent fragment renderer the HTML and PDF paths use (`mmdc`) and inlines them as data-URI images, which pandoc embeds as media. A failed diagram stays on its slide as a code block and is reported as a soft error.

## Changed

- With `-o`, a recognised output extension now picks the format (`.pptx` writes a deck, `.html` a page). PDF remains the default when the extension is unknown or absent. Previously the bare sugar always wrote a PDF under whatever name was given.
- Missing images are a hard error from pandoc rather than silently dropped. pandoc `[WARNING]` lines on an otherwise successful run are surfaced as soft errors.

## Restrictions

- pptx is refused on `content` and `clipboard` sinks (binary output, like PDF) and as a source (pandoc has no pptx reader), each with a message that names the limitation.
- Mermaid `vellum:scale` hints are ignored for pptx; pandoc sizes pictures to the placeholder.
- Decks were verified in LibreOffice headless, not in Microsoft PowerPoint itself. `.potx` templates are accepted but untested.
