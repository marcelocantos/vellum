## Same-page links in the viewer

- **`[Options](#options)` now scrolls to the heading in the HTML preview.** The viewer sets `<base href>` to the note's directory so relative images and links work. Fragment-only links resolved against it too, so clicking one went to the directory, and the viewer replied "is a directory". Fragment links in the page, including footnote references, raw `<a href=#id>` HTML and links inside Mermaid diagrams, now point at the document itself. The browser scrolls in place without a reload. Pages cached by an older version get the fix without a re-render.
- **PDF output was already correct.** `#id` links in PDFs from both WeasyPrint and Prince are internal jumps to the heading. A regression test now covers this.
- `make verify-release` now checks same-page links in the viewer page and in the PDF.
