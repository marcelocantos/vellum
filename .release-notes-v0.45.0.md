### Added

- **Folders the viewer always serves.** Since v0.43.0 the viewer serves only folders a Markdown document was opened from. `viewer.folders` in `config.yaml` now lists folders that are served from the start, with everything beneath them:

  ```yaml
  viewer:
    folders:
      - ~/work    # "/" serves everything
  ```

  Nothing in a listed folder needs opening first: links between repositories, images, reloads and non-Markdown files all load. A folder that does not exist on a machine is skipped, so one config file can serve several machines. Restart the viewer after editing the file. The default is unchanged. The cost of listing a folder is that any document you view can link to, and show images from, any file in it.

### Changed

- **The refusal for a path outside the served folders says what to do.** It named only `vellum view`. Opening a Markdown document's URL from outside a page (the address bar, `open <url>`, `vellum view`) is what serves its folder, and the message, README and agent guide now say so.

### Notes

- A reload repeats a request as it was first made. A tab that was reached by a link, or opened before v0.43.0, can be refused when reloaded; entering its URL in the address bar serves it, and so does listing its folder under `viewer.folders`.
