## Missing tools are reported up front

- **PDF conversions check their tools before starting.** `vellum doc.md`, `vellum convert … -o doc.pdf` and the MCP `convert` tool now check for the PDF backend (`weasyprint` by default, or `prince`), `node` and `mmdc` before any converter runs. Every missing tool is listed with its install command (`required dependency "weasyprint" not found on PATH …`). Before, the run failed partway through with an exec error from the backend. A DOCX → PDF run now fails before pandoc starts, rather than after.
- **pandoc is checked only when it's needed.** It is checked when a rich-text source (RTF, DOCX, HTML, ODT, …) or PowerPoint output is requested. Markdown → PDF or HTML never asks for it.
- **Stdio `vellum --mcp` starts without a dependency gate.** It used to refuse to start when WeasyPrint or `mmdc` was missing, even for calls such as DOCX → Markdown that need neither. Each call is now checked for the tools it needs, the same way as the CLI and the HTTP daemon. `--backend` together with `--mcp` used to affect only that startup check, so it no longer does anything. The backend still comes from the tool input or the config file.
- Batch `files` conversions report a missing renderer once, not once per file.
- New in the `convert` package: `PandocDep`.
