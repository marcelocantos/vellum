## Changed

- The view server no longer waits on `mmdc` or KaTeX before first paint. On a cache miss the page is converted without starting either subprocess: every Mermaid diagram and math expression arrives as a placeholder carrying a content id, and the article text is in the DOM as soon as goldmark finishes.
- Each placeholder is rendered on demand. The page fetches it from `/_vellum/fragment` when it scrolls within 1200px of the viewport, or on click, and the server renders that fragment then: one `mmdc` run per diagram, bounded by CPU count, and a document's math in a single `node` batch.
- While a fragment is in flight the placeholder animates: a shimmering box for a diagram, pulsing raw TeX for math. Both honour `prefers-reduced-motion`. A revisit reserves each cached diagram's aspect ratio so nothing below it shifts.
- No placeholder is left in a half state. A fetch the daemon did not answer retries with backoff; a render failure or a stale id shows the fragment's source, the error text, and a Retry button. Renders are detached from request cancellation, so a watch reload mid-render does not kill the `mmdc` run the reloaded page is about to ask for.
- The view cache is now two-stage. The per-document entry holds the placeholder shell only; rendered fragments are cached by content id as `frag-<id>.html`, shared across documents, written atomically and never cached on failure. Concurrent requests for one fragment, or for one document's math batch, are coalesced. The stamp format is versioned, so v0.23 whole-page entries miss and are re-rendered rather than served as complete.
- Copy resolves every fragment before writing the clipboard, so a pasted document never contains a placeholder. PDF, MCP, and CLI conversions still convert the whole document in one pass.
- Viewer images carry `loading="lazy"` and `decoding="async"` unless the author already set `loading`.
